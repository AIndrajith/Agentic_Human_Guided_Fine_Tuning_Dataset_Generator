================================================================
 SYNTHETIC DATA GENERATION — LOCAL RUN COMMANDS
 Monorepo: web_api/ and workers/ are SEPARATE uv projects.
 Run BOTH services from this repo root (imports are rooted here).
================================================================

----------------------------------------------------------------
 0. ONE-TIME — install each service's deps
----------------------------------------------------------------
cd web_api ; uv sync ; cd ..
cd workers ; uv sync ; cd ..

----------------------------------------------------------------
 1. START SHARED INFRASTRUCTURE (Docker)
----------------------------------------------------------------
docker compose up -d            # postgres, redis, qdrant, minio, flower
# postgres roles (synth_owner / synth_app) are created on FIRST start only,
# from infra/postgres/init/01-roles.sh using the passwords in .env

# (legacy, until the Mongo -> Postgres migration is finished)
docker run -d --name synthetic_data_mongo -p 27017:27017 -v mongo_data:/data/db mongo:7

# every time after:
docker compose start

----------------------------------------------------------------
 1b. DATABASE SETUP (first time, and after pulling new migrations)
----------------------------------------------------------------
cd web_api ; uv run alembic upgrade head ; cd ..              # main DB
cd web_api ; uv run alembic -x db=test upgrade head ; cd ..   # test DB
uv run --project web_api python -m web_api.scripts.setup_checkpointer          # LangGraph tables
uv run --project web_api python -m web_api.scripts.create_admin --email you@x.com --username admin

# new migration after changing web_api/db/models (review the file before upgrading!):
cd web_api ; uv run alembic revision --autogenerate -m "describe change" ; cd ..

# tests (uses synthetic_data_test; email + MinIO are faked)
uv run --project web_api pytest web_api/tests

----------------------------------------------------------------
 2. RUN THE SERVICES (two terminals, BOTH from repo root)
----------------------------------------------------------------
# Terminal 1 — web_api  (http://localhost:8000)
web_api\.venv\Scripts\activate
uvicorn web_api.main:app --reload --port 8000 --loop asyncio:SelectorEventLoop
#   --loop is required on Windows: psycopg async can't run on the Proactor loop

# Terminal 2 — workers  (--pool=solo REQUIRED on Windows)
workers\.venv\Scripts\activate
celery -A workers.celery_app worker --loglevel=info --pool=solo

# Per-service detail: web_api/README.md and workers/README.md

----------------------------------------------------------------
 3. .ENV (shared, at repo root — both services read it)
----------------------------------------------------------------
See .env.example. Key ones: DATABASE_URL, MIGRATION_DATABASE_URL, JWT_SECRET_KEY,
ENCRYPTION_KEY, MINIO_*, RESEND_API_KEY + FROM_EMAIL (unset = invite links are logged instead)
Use 127.0.0.1 (not localhost) in DB URLs: localhost tries IPv6 first on Windows -> ~2 min delay

Generate ENCRYPTION_KEY:
  web_api\.venv\Scripts\python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"

----------------------------------------------------------------
 4. VERIFY
----------------------------------------------------------------
docker ps
API:    http://localhost:8000/docs
Qdrant: http://localhost:6333/dashboard
MinIO:  http://localhost:9001  (minioadmin / minioadmin)
Flower: http://localhost:5555

----------------------------------------------------------------
 5. STOP / CLEANUP
----------------------------------------------------------------
# Ctrl+C the two service terminals
docker compose stop                     # stop infra (keep data)
docker stop synthetic_data_mongo
docker compose down -v                  # WIPE infra volumes

----------------------------------------------------------------
 6. COMMON ISSUES
----------------------------------------------------------------
- Celery hangs on tasks            -> forgot --pool=solo (Windows)
- ModuleNotFoundError web_api/...  -> not run from repo root, or wrong venv active
- `import torch` works in web_api  -> bad split; torch belongs ONLY to workers
- Connection refused 6379/6333     -> infra container not started
- "Psycopg cannot use ProactorEventLoop" -> start uvicorn with --loop asyncio:SelectorEventLoop
- Postgres password auth failed    -> .env passwords changed after first init; ALTER ROLE ... PASSWORD
                                      or (dev only) docker compose down -v to re-run init
- DB shell: docker exec -it synthetic_data_postgres psql -U postgres -d synthetic_data
- Credentials endpoints 500        -> ENCRYPTION_KEY missing
- First academic PDF very slow     -> Marker downloads models once
